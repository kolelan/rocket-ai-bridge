# Rocket AI Bridge

Мост между [Rocket.Chat](https://developer.rocket.chat/apidocs) и [DeepSeek](https://api-docs.deepseek.com/). Программа опрашивает комнаты чата и отвечает моделью DeepSeek от имени бота.

Секреты в коде не хранятся. Токен Rocket.Chat, id пользователя, id комнат, ключ DeepSeek и пароль создаваемого бота читаются из файла `.env`.

## Быстрый старт

Нужен Python 3.11 или новее.

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Дальше откройте `.env` и заполните переменные. Что писать в каждую — написано комментариями в `.env.example`. Если обязательной переменной нет, скрипт останавливается и повторяет эту подсказку.

Узнать id комнат:

```powershell
python get_rooms.py
```

Создать учётную запись бота (токен в `.env` должен принадлежать администратору):

```powershell
python create_bot.py
```

Запустить мост:

```powershell
python bridge.py
```

Остановка — `Ctrl+C`.

Проверка, что сервер и ключ DeepSeek доступны, и сколько токенов уже лежит в сохранённых чатах:

```powershell
python check_env.py
```

Для более точного подсчёта можно дополнительно поставить `tiktoken`. Без него скрипт оценивает размер как «число символов / 3».

Грубая проба лимита Rocket.Chat (30 запросов `GET /api/v1/me` с паузой 2 секунды):

```powershell
python test_rate_limit.py
```

Запросы к Rocket.Chat идут с `verify=False`: на корпоративном сервере сертификат часто самоподписанный.

## Версия 3.6

Это текущая рабочая версия. Её снимок лежит в ветке `v3.6`. Пока в `develop` нет новых коммитов, тот же код стоит на `main` и `develop`.

Мост держит два канала. В комнату управления пишут только команды. В комнату работы пишут вопросы, и туда же приходит ответ. Диалог помнится в рамках активного чата: следующий вопрос уходит в DeepSeek вместе с уже сохранённой историей.

На новый вопрос бот сразу ставит сообщение «⏳ Думаю...». Текст модели собирается до конца, и заглушка один раз заменяется готовым ответом. В комнате не мелькает черновик, а Rocket.Chat получает одно обновление вместо длинной серии правок.

Свои сообщения бот узнаёт по невидимому символу в начале текста и не отправляет их в модель второй раз. Обычный текст в комнате управления тоже не уходит в DeepSeek: бот просит писать там команды, а вопрос задавать в комнате работы.

Пока в комнатах есть новые сообщения, опрос идёт примерно раз в 3 секунды. В тишине пауза растёт до 15 секунд. Если сервер отвечает `429`, мост ждёт время из `Retry-After` и затем снова опрашивает каналы.

Картинки уходят в модель только при `!model flash`. Остальные вложения сохраняются в `media/` активного чата и в запрос не попадают. Когда оценка истории превышает примерно 40 000 токенов, старая часть срезается в `context-NNN.json`, а в запросе остаётся умещающийся хвост.

Каждый запуск пишет свой файл `log/<дата-время>_bridge.log`. В нём видны активный чат, модель, команды и длина ответа.

### Каналы

- **Управление** (`DP_CTRL_ID`) — только команды. История диалога здесь не копится.
- **Работа** (`DP_CHAT_ID`) — вопросы человека и ответы бота.

### Команды

Их пишут в комнату управления.

| Команда | Действие |
| --- | --- |
| `!new <имя>` | Новый чат, например `!new ssh-setup`. Папка `chats/2026-10-06-ssh-setup/`, он становится активным. |
| `!list` | Активные чаты. |
| `!use <chat_id>` | Переключить активный чат. |
| `!current` | Активный чат и модель. |
| `!model flash` | `deepseek-flash` — быстрая модель, в этой версии через неё идут изображения. |
| `!model pro` | `deepseek-v4-pro` — модель для текста. |
| `!arch [chat_id]` | Убрать чат в `archives`. Без имени архивируется активный. |
| `!help` | Та же справка прямо в чат. |

Обычный текст в комнате управления бот не отправляет в модель: он просит писать команды здесь, а вопросы — в комнате работы.

### Файлы на диске

Каталог — `WORK_DIR` или папка программы, если переменная пустая.

- `state.json` — какой чат и какая модель активны сейчас.
- `chats/<id>/context.json` — история, которая уходит в DeepSeek.
- `chats/<id>/context-NNN.json` — срезы истории, когда оценка размера превысила лимит (около 40 000 токенов).
- `chats/<id>/tracking.json` — курсор прочитанных сообщений комнаты работы.
- `chats/<id>/media/` — файлы из сообщений.
- `archives/` — чаты после `!arch`.
- `log/<дата>_bridge.log` — лог одного запуска.

Эти каталоги и `state.json` в git не входят: там переписка и рабочие id.

## Ветки

История линейная. Каждая ветка версии стоит на своём снимке. Новые правки идут в `develop`, выпуск остаётся на `main`.

| Ветка | Что появилось |
| --- | --- |
| `v1` | Опрос одной комнаты и потоковое обновление ответа в другой. Памяти диалога нет. Рядом `get_rooms.py`. |
| `v2` | Несколько чатов в файлах, команды `!new`, `!list`, `!use`, `!current`, `!model`. Команды и вопросы в одной комнате. |
| `v2.5`, `v2.6` | Комната команд отдельно от комнаты вопросов. Бот пропускает сообщения, которые отправил сам. Ветка `v2.6` указывает на тот же коммит: сохранённые файлы v2.5 и v2.6 совпадали. В тексте v2.5 вложения обещаны «в v2.6», отдельной реализации в том снимке нет. |
| `v3` | Папка на чат, вложения и картинки, архив `!arch`, обрезка длинного контекста, пауза после `429`. |
| `v3.5-stream` | Файл лога, невидимая метка своих сообщений, ответ обновляется по мере генерации, опрос реже в тишине. |
| `v3.6` | Текущая версия: свой лог на каждый запуск и один финальный ответ вместо серии правок во время генерации. |
| `main` | Сохранённый выпуск. Сейчас совпадает с `v3.6`. |
| `develop` | Ветка для следующих правок. Сейчас тоже совпадает с `v3.6`. |

`create_bot.py` добавлен между v2 и v2.5. `check_env.py` — между v2.5 и v3: сначала проверка доступности, следующим коммитом подсчёт токенов в контексте. `test_rate_limit.py` — между v3.5 и v3.6.

Посмотреть снимок:

```powershell
git switch v3
```

Текущая версия: `git switch v3.6`. Дальнейшие правки — в `develop`.

## Секреты

В коммитах не должно быть токенов. Перед публикацией это проверялось поиском по всей истории.

Локальный `.env` остаётся только на машине. Туда же собраны значения, которые раньше стояли прямо в исходниках.

Ключи уже побывали в рабочих файлах. Имеет смысл выпустить новые: пересоздать Personal Access Token в Rocket.Chat, ключ на platform.deepseek.com и пароль бота, затем вписать новые строки в `.env`. Старые после этого отозвать.

Файлы `*.py.back` — локальные снимки, они в `.gitignore`. В репозиторий их класть не нужно: те же версии лежат в ветках, уже без ключей.
